# ADR-0041 · 广告调整事实与效果复盘分层，不做因果冒充

- **日期**：2026-09-04
- **状态**：已采纳
- **依据**：广告调整复盘中心一期方案及维护者确认

## 背景

现有 `audit.jsonl` 证明一次写调用是否成功，审批库证明谁批准了什么，影子模式估算「若执行」的
机会成本，指标层提供广告和业务数据。它们都不能完整回答运营问题：某个广告或关键词在什么时候
改了什么、为什么改、当时依据什么、影响了父体下哪些投放子体，以及调整后广告和整条链接的数据
如何变化。

把这些问题塞回技术审计会混淆「HTTP 请求成功」和「业务效果变好」；仅凭报表反推动作又会丢失
原始理由、前后值和动作时点。父 ASIN 也不是广告写入对象，直接把父体当目标会把链接级分析和
实际投放对象混在一起。

## 决策

1. 建立独立 SQLite 事件账本 `~/.awen/adjustments.db`。动作是不可变事实，人工注释与复盘结果
   追加保存；同一复盘窗口的数据回补形成新 revision，不覆盖旧结论。
2. 操作事件与效果指标分层。事件来自上游推送、awen 成功写入或领星 v2 操作日志；效果通过
   `metrics` canonical 契约读取。账本不保存 OpenAPI 凭据、访问令牌或刷新令牌。
3. 每个店采用 `push`、`lingxing` 或 `hybrid` 来源模式。默认 `hybrid`：36 小时内收到上游推送
   就不跑领星；推送不新鲜才用领星兜底。不同来源之间不做模糊去重或模糊回滚匹配。
4. 父子范围记录父 ASIN、实际投放的子 ASIN、同父体未投放的兄弟 ASIN。上游随动作提供的 T0
   快照可视为动作时点范围；awen 原生候选在进入审批/执行链前按店铺捕获决策时快照；历史领星日志
   只能结合本次同步时快照。后两种必须标记 `action_time_exact=false`，不得伪装成历史 T0。父 ASIN
   只用于分析，永不成为广告写入目标；`advertised_asin` 与
   `purchased_asin` 始终是两个字段。
5. 复盘固定使用 3/7/14/30 天等长前后窗，T0 排除；正式趋势用非重叠的 D1–D3、D4–D7、
   D8–D14、D15–D30 分段。比率从汇总分子分母重算，不平均子体 ACoS/CVR。
6. 结论只描述观察到的信号。样本、数据完整度、对象映射、窗口可比性分别给置信度，总置信度取
   最弱项；同窗多次调整、价格/促销/库存/Listing 等混杂存在时标为 `confounded`，不声称因果。
7. 复盘链路只读。负向复盘不会直接生成或执行补救动作；如需再次调整，必须重新进入现有优化器、
   护栏和人工审批链。周报/月报也只汇总，不创建重复审批。
8. T0 以站点本地日期为准。原生写入只查本地元数据，不在成功写入后追加网络请求；未知时区按 UTC
   降级但必须留下低置信度警告。购买商品归属优先依赖 `advertised_asin`；多父体场景缺少该字段时
   宁可返回数据缺口，也不把跨父体购买误报成兄弟体 halo。

## 理由

- 技术审计、业务动作和效果证据生命周期不同，独立存储可避免任何一层改动污染安全写入链。
- 上游推送拥有最完整的决策上下文，领星日志适合做事实兜底；hybrid 新鲜度切换比跨来源模糊匹配
  更可解释，也不会把两个真实动作错误合并。
- 亚马逊归因存在延迟，父体链接还会同时受到自然流量、价格、库存和促销影响。把相关性写成因果
  会让后续自动优化建立在错误前提上，因此证据边界必须由确定性代码输出。

## 否掉的方案

- **扩展 `audit.jsonl`**：它面向写接口与回滚，不适合上游/亚马逊后台人工操作，也不适合多版本
  效果复盘。
- **从报表差分反推动作**：只能看到数值变化，无法可靠还原操作者、理由和准确时点。
- **一期做完整执行对账与自动回滚**：领星日志没有稳定行 ID，不同来源也没有共同主键；模糊匹配
  一旦错配会回滚错误对象。只有 awen 本地审计号明确关联的显式回滚才记录 exact relation。
- **把父 ASIN 当广告实体**：父体通常不直接投放，这会破坏已有 campaign/ad group/keyword/
  product-ad 的真实写入契约。

## 后果

- 新增一个本地 SQLite 数据库和每日同步/复盘任务，但不增加第三方依赖。
- 没有父子快照或高层报表时，系统会保留动作并明确显示 `data_gap`/低映射置信度；数据非空但全部
  落在当前对象范围外时也视为数据缺口，不会编造链接效果或把范围外数据当作零表现。
- 首次同步映射失败时，后续同源幂等重放可补齐缺失的父子 scope 和映射证据；核心动作、原始理由与
  前后值仍保持不可变。
- awenOps 可分别提交对象、广告组、活动、业务、购买商品、利润、排名、库存和店铺数据；显式空数组
  代表该维度的数据缺口，不代表零表现。
- awenOps 可以通过新增 API 构建独立复盘页面；一期不要求本仓库实现前端。
- 后续新增广告产品或数据源时，应实现 canonical metric 或 operation-source 适配器，不得把供应商字段
  直接泄漏到复盘规则。

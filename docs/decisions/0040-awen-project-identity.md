# ADR-0040 · 项目标识统一为 awen

- **日期**：2026-09-04
- **状态**：已采纳
- **依据**：维护者确认的全量品牌与技术标识迁移

## 背景

仓库名称已经使用 `awen-agent`，但 Python 包、发行包、命令行、本地状态目录、环境变量、
安装部署脚本和嵌入式工作台仍使用另一套历史标识。两套名称同时存在会让安装来源、模块导入、
运行目录和消费方契约长期漂移，也会让后续发布无法判断哪一套才是规范名称。

## 决策

项目只保留一套规范身份：

- 产品显示名为 `awen Agent`，嵌入式工作台显示名为 `awenOps`；
- Python 包为 `awen_agent`，发行包为 `awen-agent`，命令行入口为 `awen`；
- 本地状态目录为 `~/.awen`，项目专用环境变量统一使用 `AWEN_*`；
- systemd、安装器、离线包、日志前缀、HTTP 元数据、站点、文档和测试同步迁移；
- Agent 仓库链接指向 `zheng-zhengwen/awen-agent`，工作台参考链接指向
  `zheng-zhengwen/wen-System`；
- 保持 `/v1/*` HTTP 资源路径和 Amazon 业务契约不变；
- 不提供旧命令、旧模块、旧环境变量或旧状态目录的兼容层。

## 理由

兼容层会继续把旧标识留在代码、安装器和运行时分支中，与“全量统一”的目标冲突。当前迁移由
维护者明确授权接受破坏性变化，因此一次性统一比长期维护双入口更容易验证，也更适合后续独立发布。

## 后果

- 现有安装需要重新安装 `awen-agent`，并把需要保留的本地配置和数据主动迁移到 `~/.awen`；
- 自动化脚本和部署单元必须改用 `awen`、`AWEN_*` 与 `awen-*.service`；
- 工作台消费方需要同步更新显示名、服务单元名和工具标识；
- 后续新增代码不得再引入第二套项目身份，CI 应通过全仓标识扫描守住这一约束。

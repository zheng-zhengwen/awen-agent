# awen Agent 使用与操作文档

> 自托管的**亚马逊运营对话式 Agent**。专长广告巡检（确定性规则引擎 + LLM 复核 + 护栏 + 审核制写入 + 审计回滚），也能干日常运营杂活（读 Excel、算数、写报告、查网页）。
> 哲学：**证据驱动、写操作一律人工审批、数据私有**。

---

## 一、安装

```bash
# 方式 A：装 Release 里的 wheel（任何人可用）
pip install https://github.com/zheng-zhengwen/awen-agent/releases/download/v0.4.0/awen_agent-0.4.0-py3-none-any.whl

# 方式 B：从源码（pipx，装完任意目录敲 awen）
pipx install git+https://github.com/zheng-zhengwen/awen-agent.git

# 方式 C：克隆后开发安装
git clone https://github.com/zheng-zhengwen/awen-agent.git && cd awen-agent
pip install -e ".[anthropic]"     # anthropic 可选(用 Claude 才需要)
```
跨平台纯 Python（≥3.9），Windows/macOS/Linux 均测过。

## 二、首次运行（引导）

直接敲 `awen`，**首次会自动进引导**（也可手动 `awen onboard`）：

1. **选主脑模型并配 key/provider** —— 推荐 DeepSeek（便宜、工具调用稳）；也可 Claude API（需 `ANTHROPIC_API_KEY`）、Gemini API（需 `GEMINI_API_KEY`）、AWS Bedrock（需 `boto3` + AWS 凭据链）、OpenRouter、Kimi、通义、Z.AI、MiniMax、xAI、Ollama、本地/自定义 OpenAI 兼容端点。
2. **（可选）接领星 OpenAPI** —— 拉真实广告数据 / 写回。填 host / appId / appSecret。
3. **（可选）生成 `AGENTS.md`** —— 写你的长期打法/边界，对话时自动注入。

配置都存在本机 `~/.awen/`（`.env` 密钥 600 权限，`settings.json`，`mcp.json`）。

## 三、两种用法

### 1) 对话模式（推荐）
```bash
awen                      # 进对话；裸敲即可
awen --continue           # 续接上次会话
awen chat --resume <id>   # 续接指定会话
awen --raw                # 原始流式输出（默认 Markdown 渲染）
```
直接说人话，它自己编排工具：「看下 sid 1863 这周广告」「读 /path/report.csv 帮我分析」。写操作一律弹**人工审批**。

**斜杠命令**：
| 命令 | 作用 |
|---|---|
| `/help` | 命令与用法 |
| `/model` `/config` | 切模型/配 key、配置向导 |
| `/plan` `/approve` | 进/出**计划模式**（只读，不写）；批准后执行 |
| `/cost` | 本会话 + 今日 token 用量与成本估算 |
| `/compact` | 手动压缩上下文（LLM 摘要历史，省 token，摘要入库） |
| `/compact auto on/off/status` | 开启、关闭或查看自动压缩；默认关闭，长任务只提醒不打断 |
| `/init` | 生成账户指令模板 `AGENTS.md` |
| `/memory` | 记忆状态 / `/memory <词>` 检索 |
| `/reflect` | 立刻把最近的零散经历提炼成分类记忆（会话结束也会自动跑） |
| `/skill` | 搜索可复用运营 Skill；`/skill 否词` |
| `/workspace` | 项目理解：`/workspace map --root .` |
| `/patch` | 结构化补丁：`/patch validate patch.json --root .` |
| `/gitops` | Git 工作流：`/gitops status --root .` |
| `/tools` `/mcp` | 列工具 / MCP 服务器 |
| `/raw` `/clear` `/exit` | 切渲染 / 清上下文 / 退出 |

对话中可直接说「**记住**…」沉淀打法、「**回忆**…」跨会话召回。
工程类问题会自动注入精简工程上下文，包括 workspace 入口/测试/配置、git 状态和 skill 状态；运营类问题仍优先注入 Amazon skills 与知识库。

长代码任务或资料整理任务默认不会自动压缩上下文，避免做到一半被摘要打断。上下文过长时会提示你手动 `/compact`；如果你确实想自动压缩，可执行 `/compact auto on`。单轮工具调用上限默认 48 步，接近上限时会提前提示，达到上限时可直接说「继续」，系统会把续跑指令写回上下文，避免重复已成功的工具调用；也可用 `awen config set chat_max_tool_steps 80` 调高。复杂任务可先 `awen task create ...`，再用 `awen chat --task-id <task-id>` 绑定对话；工具预算中断会自动写入 task 日志和结构化 `resume`，之后 `awen task resume <task-id>` 或 `/v1/tasks/<id>/resume` 查看续跑点，也可以用 `awen task continue <task-id>` 或 `/v1/tasks/<id>/continue` 直接跑一轮续接。工程类对话会显示 `Code 计划 → 读上下文 → 修改/生成补丁 → 测试 → 复查`，工具调用也会带进度编号，便于看清它正在做哪一步。终端默认使用带框输入区（输入框钉在底部，提交后输入回显为历史、对话自上而下累积）；若想退回轻量单行输入，可设置 `AWEN_BOXED_INPUT=0`。

模型配置对齐 Hermes 的核心是 provider profile，而不是写死几个模型名：

```bash
awen model providers       # provider、认证方式、key 状态、能力标签、可用性
awen model doctor          # 当前模型、认证状态和 provider 能力体检
awen model list            # 完整模型/别名清单
awen model openrouter:anthropic/claude-sonnet-4.6
awen model ollama:qwen3-coder
awen model auth            # OAuth/Bearer provider 登录状态
awen model auth qwen-oauth --login
awen model auth qwen-oauth --device-code
awen model auth qwen-oauth --token <access_token>
awen model auth qwen-oauth --import-qwen-cli
awen model auth qwen-oauth --refresh
awen model auth qwen-oauth --probe
awen model auth openai-codex --device-code
awen model auth openai-codex --refresh
awen model auth openai-codex --probe
awen model auth google-gemini-cli --login
awen model auth google-gemini-cli --login --no-browser
awen model auth google-gemini-cli --project <gcp-project-id>
awen model auth google-gemini-cli --probe
awen model auth copilot --exchange
awen model auth copilot --probe
awen model logout qwen-oauth
```

`model providers` 会显示能力标签：`tools` 工具调用、`stream` 流式、`vision` 多模态视觉、`models` 可刷新模型清单、`probe` 可发起真实可用性探测、`local` 本地端点。awenOps 可读取 `/v1/model/providers` 获取同一份 provider 能力矩阵，不需要前端硬编码模型表。

`--token`、`--login`、`--device-code` 只代表本地已保存凭证；`--probe` 会发起一次真实请求验证模型、权限、配额和 transport 是否可用，并隐藏 token。

当前可直接作为主脑使用：Claude API、Gemini API、Gemini Code Assist OAuth 登录/token/项目保存/gcloud project 发现/真实 probe 诊断、AWS Bedrock Converse、OpenAI 兼容端点、OpenAI Codex OAuth Responses streaming、DeepSeek、通义、Kimi/Moonshot、Z.AI/GLM、豆包、MiniMax、OpenRouter、Nous(API key)、xAI、GitHub Copilot chat/completions、Ollama/本地、自定义网关，以及 Qwen OAuth device-code/Qwen CLI 登录导入与 refresh token 自动刷新形态。Gemini Code Assist 的 Google 控制台开通/配额调整仍需用户人工完成；Qwen 官方文档说明 OAuth 免费层已于 2026-04-15 停用，可能被服务端拒绝，生产建议使用 DashScope/Coding Plan/API key；不要理解成普通 Codex/Claude 网页会员登录。

### 1.1) 代码 Agent 闭环

awen Agent 的通用代码能力不是直接“猜着改”，而是固定走一条可审计链路：项目索引 -> 任务规划 -> 代码上下文 -> 结构化 patch -> 测试 -> 失败修复计划 -> 审查门禁。

```bash
awen workspace index --root .
awen code plan "修复登录超时重试逻辑" --root .
awen code context "修复登录超时重试逻辑" --root .
awen code bundle "修复登录超时重试逻辑" --root .
awen code brief "修复登录超时重试逻辑" --root . --budget 6000
awen code quality --root .
awen code diff-brief --root .
awen code release-check --root . --version v0.5.7
awen workspace symbols RetryPolicy --root .
awen code impact RetryPolicy --root .
awen code refs RetryPolicy --root .
awen code rename-plan RetryPolicy --new-name RetryConfig --root .
awen code patch "修复登录超时重试逻辑" --root . --llm
awen code run "修复登录超时重试逻辑" --root . --llm-patch --max-rounds 3
awen code runs
awen code sandbox --root .
awen patch validate patch.json --root .
awen patch apply patch.json --root . --execute
awen code test --root . --command "python -m pytest"
awen code repair --root . --output-file pytest.out
awen code review --root .
```

关键点：

- `workspace index/search/explain` 会记录 Python 的类、函数、方法、行号、导入和调用；JavaScript/TypeScript 会提取类、函数、导出常量和调用名，便于快速定位影响面。
- `workspace symbols` 用于查符号定义；`code impact` 用于查定义、导入方、调用方和受影响测试。
- `code refs` 查定义、导入、调用和文本引用；`code rename-plan` 生成重命名 patch 草案，仍需人工 validate/apply。
- `code brief` 按字符预算输出分层上下文，适合喂给模型或人工快速审查。
- `code quality` 做本地确定性质量扫描：大文件、长函数/方法、高连接度模块、测试覆盖风险。
- `code diff-brief` 根据 git diff 生成变更摘要、建议测试和 PR 草稿。
- `code release-check` 汇总发布前只读门禁：git 状态、review gate、quality、release-plan 和建议测试。
- `code plan` 输出相关文件、步骤、风险、建议测试，并读取 `AGENTS.md`、`CLAUDE.md`、`README.md`、`pyproject.toml`、`package.json` 中的仓库约定。
- `code context` 把相关文件和仓库约定压成适合模型/人工审查的上下文。
- `code bundle` 把 plan/context/impact/quality/patch 模板/selected_tests/repair/resume_prompt 打成只读任务包，适合 awenOps 展示多轮代码任务并从断点继续。
- `code test` 会运行测试并解析 pytest 失败摘要。
- `code repair` 会把失败用例映射回测试文件和疑似生产代码，指导下一轮最小 patch。
- `code patch --llm` 默认只生成模型请求包；加 `--call` 才调用当前模型，调用后也只做 dry-run validate，不会 apply。
- `code run --llm-patch --max-rounds N` 会保存一次任务记录，并输出多轮 dry-run 状态；后续轮次等待人工 apply/test/repair 输入。
- `code runs` / `code show <id>` 用于查看已保存的 code run。
- `code sandbox` 只输出 worktree/临时目录沙箱计划，不会创建目录。
- `code review` 汇总 git diff、确定性风险扫描和建议测试。
- 这些命令不会提交、推送或发版；写文件只通过 `patch apply --execute` 明确发生。

### 2) 命令式（脚本/自动化）
```bash
# 领星店铺维度巡检（真实广告数据）
awen lingxing setup                       # 配凭据
awen lingxing probe                       # 自检（取令牌+店铺）
awen lingxing sellers                     # 列店铺拿 SID
awen patrol --from-lingxing --sid 1863 --days 30          # 只读巡检（带缓存+进度条）
awen patrol --from-lingxing --sid 1863 --days 30 --execute # 巡检 + 逐条人工审批写入

# CSV 巡检（无领星凭据也能用）
awen patrol 搜索词报告.csv --asin B0XXXXXXXX --site US

# 通用 MCP 数据源/写入映射（非领星广告源）
awen mcp add
awen mcp tools <名称>
awen mcp suggest <名称> <工具> --args '{"asin":"{asin}","site":"{site}","days":"{days}"}'
awen mcp validate <名称>
awen mcp doctor
awen mcp self-config
awen mcp serve
awen apply 巡检输出目录 --execute --from-mcp 领星          # 审核制执行(MCP 写映射)

# 审计/回滚
awen audit list
awen audit rollback <审计ID>
```

`mcp doctor` 会检查 transport、dataSource、writeActions 和安全风险；带鉴权的远程 MCP 建议使用 HTTPS，stdio 命令必须在 PATH 中。即使 writeActions 配好，真实写入仍必须显式 `--execute`，并进入人工审批和审计。

`mcp serve` 是反向 MCP：把 awenAgent 的只读能力暴露给其它 MCP 客户端，包含知识检索、统一检索、Skills、system doctor、task list/detail/resume、trace list/stats、workspace 搜索/巡检、code plan/context/bundle/repair。默认不暴露写文件、执行命令或广告写入工具。

### 3) ASIN 深度审计（COSMO / Rufus）——配一个数据源 MCP 即可用

内置技能 `amazon.asin_cosmo_rufus_audit` 对单个 ASIN 做证据驱动审计（语义检索 / COSMO / Rufus /
Listing 转化 / 广告就绪），输出 11 板块报告 + 结尾结构化 JSON。它**不绑定任何厂商**：审计时先
`mcp_list_tools` 发现你配置的数据源工具，再 `mcp_call_tool` 按 ASIN 抓页面 / 评论 / Q&A / 竞品。

**克隆本仓库后，只需配置一个「可信」的数据源 MCP 即可跑：**

```bash
awen mcp add            # 传输选 http/sse/stdio，填数据源 URL/命令
                         # 最后一问「信任此服务器？免审批」选 y —— 无人值守取数必须信任
awen doctor             # 检查是否已有 trusted 数据源 MCP（没有会 warn）
```

数据源可以是任何能按 ASIN 返回产品 / 评论 / 竞品数据的 MCP（如 sorftime、卖家精灵，或你自建的抓取
MCP）。配好后，awenOps 工作台「分析工具 → ASIN 深度审计」选 awenAgent 即可跑；未配数据源时
agent 会明说「未检测到数据源」并给配置指引，而不是臆造数据。

> 为什么要「信任」：非 trusted 的 MCP 调用会弹人工审批，后台审计任务无人点，会卡住。信任 = 该
> 服务器的工具调用免审批（写类操作另有独立护栏）。

## 四、安全护栏（动钱的底线）

- **写操作永远人工审批**：多档选项 `[1]是 [2]本会话都允许此类 [3]否 [4]改一下 [5]全部停`。
- **领星写总闸 operate**：`awen lingxing operate on|off|status`，**默认关**（关时只 dry-run 预览），开了也带 120 分钟自动过期。
- **硬护栏**（代码强制，LLM 绕不过）：否词 ≥15 点击 0 单才否；单次调 bid ≤±20%、步长 ≤15%；冷却 7 天；不否品牌词/竞品词/核心品类词/保护词；不投 SBV / 不操控评论；写失败自动**熔断**关开关。
- **记忆护栏**：你否过的词，下次巡检自动拦截、不再反复建议。
- **成本护栏**：`awen config set daily_cost_limit_cny 20` 设每日上限，超了暂停问你。
- **回滚**：每次写入留审计快照，`awen audit rollback <ID>` 一键回滚（否词→归档、调 bid/预算→还原旧值）。
- **计划模式 / 影子模式**：见下。

## 五、影子模式（重点）——动钱前先用数据换信任

> **这是 awen Agent 独有、Claude Code/Codex/Hermes 都没有的能力。**
> 一个会动你广告预算的 Agent，最大的门槛是「我凭什么信它」。影子模式解决这个：
> **它先只看不写、把每条建议记下来，过几天用真实花费回测「如果当时照做，能省多少 / 多抓多少单」**——用你自己账户的真实数据证明它值得信，你看准了再放它真动手。

### 5.1 它怎么工作

1. **记账**：每次 `awen patrol --from-lingxing` 巡检，都会把候选建议（否词/收割/降bid/加bid/加预算）连同**当时的触发指标**记进影子台账（`~/.awen/shadow.db`）。同一店铺+杠杆+词 7 天内不重复记。
2. **只看不写**：开了影子模式后，即使你 `--execute`、即使 operate 开关是开的，**也绝不写广告**——只记录、不执行。这是比 operate 更强的一层「绝不动手」保险。
3. **回测**：过几天再 `awen shadow report`，它会**拉这几天的真实搜索词数据**，和当初记的建议对账：
   - **否词**：当初建议否的词，之后**还烧了多少钱、且仍 0 单** → 这就是「如果当时照做能省下的钱」。
   - **收割**：当初建议升精准的词，之后**又出了多少单** → 这就是「如果当时照做能抓住的增量」。
   - **诚实**：当初建议否、但后来**真转化出单**的词，**不计入节省**（不夸大、不给自己邀功）。

### 5.2 命令

```bash
awen shadow on                       # 开影子模式：巡检只记不写
awen shadow off                      # 关：恢复正常审批写入（仍需 operate 开关）
awen shadow list [--sid 1863]        # 看台账里记了哪些建议
awen shadow report --sid 1863 [--days 14]   # 拉近 N 天现况回测，出信任报告
```

### 5.3 推荐工作流（新店/新用户）

```
第 1 步  awen shadow on                              # 进影子模式
第 2 步  awen patrol --from-lingxing --sid 1863      # 跑巡检(只记不写)，隔几天跑一次，攒台账
   …    （这期间它一个广告都不会动）
第 3 步  awen shadow report --sid 1863               # 过 1~2 周，看"若照做的收益"
第 4 步  信任建立后：
        awen shadow off                              # 关影子模式
        awen lingxing operate on                     # 开领星写总闸
        awen patrol --from-lingxing --sid 1863 --execute   # 逐条人工审批，真动手
```

### 5.4 信任报告长什么样

```
# 影子模式信任报告 — sid 1876
> 回测了 4 条有后续数据的建议。
- 否词：2 个词若当时照做，至今已省 ¥32.50（之后仍纯烧钱0单）。
- 收割：1 个词若当时升精准，至今多抓 9 单。
  · 否词「karaoke remote」之后又烧 ¥21.50(0单) → 若照做已省
  · 否词「cheap mic」之后又烧 ¥11.00(0单) → 若照做已省
  · 收割「studio mic pro」之后又出 9 单 → 若照做已抓住
```
> 注意：上例里第 3 个被建议否的词后来转化出单了，报告**没有**把它算进节省——这种「不替自己邀功」的诚实，正是信任的来源。

### 5.5 影子模式 vs 计划模式 vs operate 开关（别混）

| 机制 | 作用范围 | 行为 |
|---|---|---|
| **计划模式** `/plan` | 单次对话 | 当轮只读、不调写工具；`/approve` 后才执行。临时「先别动手，给我看计划」 |
| **影子模式** `shadow on` | 持续，跨会话 | 巡检只记不写 + 回测换信任。长期的「先观察攒数据」 |
| **operate 开关** `lingxing operate on` | 领星写入总闸 | 关=dry-run，开=允许真写（仍需逐条审批）。影子模式开时，operate 即使开也不写 |

**优先级**：影子模式开 > operate 开关。只要影子模式开着，就绝不写。

## 六、记忆（越用越懂你的店）

长期记忆全部存在本机 `~/.awen/` 下，**不依赖向量库、也不依赖任何外部记忆服务**，断网照用。

### 6.1 三层记忆（各司其职）

| 层 | 存哪 | 特点 |
|---|---|---|
| **核心记忆** | `USER.md`（运营画像）/ `AGENTS.md`（账户打法与边界）+ 项目目录 `./AGENTS.md` | **每轮常驻上下文**，不用检索就一直知道。Agent 可自己增删改；`/init` 或 onboard 生成模板 |
| **分类记忆** | `memory/<分类>/<名字>.md` | 一事一文件，分类为 `user / feedback / project / reference / domain`。索引层（每条一行）全量注入，正文按需取 |
| **情景记忆** | `memory.db` | 巡检、决策、对话片段入库，供模糊回忆 |

### 6.2 它自己会记 —— 你不用手动编辑文件

- **常驻画像自写入**：你说「以后都用中文汇报」「品牌词永远不否」，Agent 会自己写进核心记忆，**下一轮起长期生效**。
- **合并优先于新建**：写入走 add / update / delete / noop 四操作并自动查重，同一件事不会分裂成好几条。
- **新洞察先进待定区**：反思推断出来的东西不直接生效，先放 `memory/.pending/`。**同一条被观察到 3 次**才自动转正（转正后仍标「推断」，置信度封顶 0.70）；你 `memory confirm` 亲自点头的才拿满置信度。
- **推断和原话分得清**：推断记忆**永远不会**自动获得你亲口说过的规则那种权重。
- **多端并发安全**：CLI / serve / awenOps 同时写不会产生重复条目（跨进程文件锁 + SQLite WAL）。

```bash
awen memory pending          # 看待确认的推断（第几次观察到、凭什么）
awen memory confirm <名字>   # 确认转正（reject 丢弃）
awen memory reflect          # 立刻把最近的经历提炼成记忆；对话里也可用 /reflect
```

> 会话结束会自动跑一次反思，不用你每次手动 `reflect`。

### 6.3 怎么找回来 —— 两层检索 + 中文/语义双路

- **两层检索省 token**：上下文里只放记忆目录（每条一行），需要哪条才取正文，而不是把全部记忆塞进去。
- **中文检索打底**：bigram 分词 + BM25，「广告花钱太狠」能召回「广告花费太高」；ASIN / SKU 整词保留，不会串号。
- **语义并行一路**：配上 embedding 后端会再走一路向量召回，两路用 RRF 融合。实测口语化提问 recall@1 从 0.80 提到 0.93（配置见 6.7，不配也能用，只是少一路）。
- **会联想**：召回一条记忆时，把它 `[[链接]]` 到的相关记忆一并带出来。
- **事实有有效期**：「旺季 ACoS 35%」这类会变的事实带 `valid_from` / `valid_until`，过期自动退出检索；旧值归档而不是覆盖，随时能查「什么时候改的、之前是多少」。
- **跨会话回忆**：`awen memory search <词>`，或对话里直接说「回忆一下…」。

### 6.4 会遗忘、可追溯、可量化

- **会遗忘**：按「最近用没用过 / 用得多不多 / 可不可信」打分。**半衰期 45 天**（一个完整旺淡季切换周期没被召回，分数掉一半），总分低于 **0.25** 退出常驻索引层——但**仍然可以检索到，绝不静默删除**。新记忆有 **14 天保护期**，不会因为「还没被用过」就被判低分。红线规则可以 `pin` 住，永不降级。
- **可追溯**：`awen memory why <名字>` 回答「你凭什么这么认为」——来源、置信度、依据一并给出；`awen memory history <名字>` 看这条改过几次、之前是什么。
- **可量化**：内置评测框架，改检索策略前后各跑一遍就知道有没有变好，不靠感觉。

```bash
awen memory decay            # 活跃度排行：谁常驻上下文、谁被降级了
awen memory pin <名字>       # 钉住，永不降级（unpin 取消）
awen memory eval --generate  # 先用模型从现有记忆反向生成评测集（只需一次）
awen memory eval --compare   # 再跑：纯词法 vs 混合，量化语义增益
```

### 6.5 运营场景里的记忆

- **决策记忆**：你的每次否决 / 批准都记下来 → 下次巡检**自动拦截你否过的否词和调价**，不再反复建议。
- **冷却期**：同一对象刚动过就不再重复调，默认 **7 天**（`lingxing_cooldown_days` 可改）。
- **多店铺隔离**：记忆可绑 `scope`，US 站的打法不会串到 JP 站。
- **ASIN 笔记**：`awen memory note B0XXX` 看某个 ASIN 的历史笔记。

### 6.7 语义检索（默认已开，不用配）

包里带了一个 24MB 的 bge-small-zh（ONNX int8），随 awen-agent 一起装好，
**不需要 API key、不需要联网、不需要 torch**。用户换个说法提问也能召回。

```bash
awen retrieval embeddings          # 看它是否真的生效（第一行直接给结论）
awen retrieval embeddings --probe  # 真编码一次做验证
awen memory embed                  # 预热：把现有记忆一次性向量化
```

**首次为什么建议跑一次 `awen memory embed`**：一条记忆编码约 240ms，没预热的话
检索会现算。检索里有 1.5 秒的时间护栏（超了这轮就只走词法，下次再补几条），
所以不会卡死，但预热过的库检索质量才是完整的。

实测（153 条口语化提问 / 52 篇中文记忆，问题措辞由模型改写、不含原文词）：
MRR 0.381 → 0.483（+27%），关键词检索召不回的 64 条里净多召回 9 条。

想要更强或想关掉：

```bash
# 远端 embeddings 接口（模型更强，但记忆正文会出网）
awen retrieval embeddings --backend api \
    --api-base https://<供应商>/v1 --api-model <模型名> --api-key-env EMBEDDING_API_KEY

# 本地完整模型（约 2G 内存）。注意一键脚本装的是 pipx 环境，
# 用 pip install 装到系统 Python 里 agent 根本看不见：
pipx inject awen-agent sentence-transformers
awen retrieval embeddings --backend sentence-transformers --model-path <模型目录>

# 只要关键词检索
awen retrieval embeddings --backend sparse
```

- **专业知识检索与引用**：注册/身份验证、上架报错、店铺绩效、政策、费用、Listing、FBA、广告和算法类问题会按风险触发检索。证据以 `[K#]` 绑定到具体结论，最终只列出实际采用的来源；回答必须区分官方事实、账户数据推断与运营假设。算法未被官方披露时不得包装为官方规则。
- **授权账户证据**：`knowledge evidence-plan/apply/list/schema` 用于 Seller Central 通知、case、上架错误、费用、税务、结算、退货索赔和品牌保护等私有证据。必须声明 `authorized=true` 和 `rights_confirmed=true`；系统专项脱敏邮箱、电话、地址、身份、银行/卡号和税号，账户/case/notification/order/claim/settlement/transaction 标识只保留哈希引用，不保存原始文件。未带 `--confirm` 不写入。
- **广告与流量证据**：`knowledge ads-capabilities/ads-analyze` 提供带日期的广告产品能力矩阵，并分析 `advertising_report` / `traffic_experiment`。只从明确字段计算 CTR/CPC/CVR/ACoS/ROAS，零分母返回空值；缺失时区、币种、报表、归因或销售范围会降级。实验结果只标为账户观测或账户推断，不生成“流量池、权重、广告提升自然排名”等官方算法结论。需要入库时仍走 `evidence-plan/apply` 的授权、脱敏和确认流程。
- **知识库审计**：`knowledge audit` 显示来源类型、可信度、更新时间；`knowledge sources` 按 source_url/source_type/license/category 聚合知识卡，标记缺失来源、过期和 review_required。`knowledge official-sources` 展示官方来源的 authority/evidence/marketplace/locale/update policy；`knowledge sync` 只保存公开来源快照和变更 hash/diff，变更进入 `knowledge changes` 审核队列，不会自动污染生产知识。Seller Central 登录后文档标记为授权导入，不绕过认证。
- **治理与审核**：每条官方来源变更都有稳定 `chg-*` ID。`knowledge review` 必须带 `--confirm`，并在写入审核台账前验证快照 hash；本地 CLI 审核绑定本机操作者，awenOps 管理员审核使用共享 API token 的 HMAC 身份断言，未验证的 approved 不能生成发布草案。`changes/{event_id}/packet` 返回官方 diff/快照摘录和候选知识卡，`changes/draft` 生成带 event/hash 的运行时更新草案，`changes/apply` 再次确认后才发布并写入 publication 台账；网页快照不会自动成为知识正文。用户知识写入使用跨进程锁、旧 hash 乐观并发校验和不可变版本快照，`versions/rollback` 回滚时也会生成新版本。`governance/coverage/freshness/quality` 分别提供总看板、站点覆盖、时效状态和 41 项持续评测。预警会提示待审积压、未验证批准、已批准未发布、过期卡、监控错误/逾期和冲突。
- **用户知识库**：`knowledge plan/apply` 先对本地 Markdown/TXT 生成 hash 和 unified diff，带 `--confirm` 才写入 `~/.awen/knowledge/` 并可重建索引；`knowledge import/url/rebuild/index/conflicts` 仍保留给快速导入和维护。来源记录在 `sources.jsonl`，含 license/body_hash；SQLite FTS5 索引写入 category/freshness/source_quality 等治理字段，冲突审计会提示用户知识与官方知识的潜在矛盾。
- **统一本地检索**：`retrieval index/search/status/sync` 会把内置/用户知识卡和长期运营记忆写入同一个本地 SQLite 索引；默认 `local_hash_embedding_v1` 不依赖 GBrain/Ollama。`retrieval status` 暴露 `needs_rebuild` 和 source fingerprint，`retrieval sync` 只有在知识/记忆内容变化时才重建（换 embedding 后端**不会**触发重建——索引这一层固定用稀疏向量，重建出来还是同一批东西）；awenOps 可直接调用 `/v1/retrieval/search` 做统一召回，或向 `/v1/retrieval/index` 传 `{"sync": true}` 做轻量同步。
- **结构化画像**：除目标 ACOS/保护词外，支持毛利率、盈亏 ACOS、售价、Listing 风险，自动注入对话。
- **Listing 转化诊断**：`listing audit` 根据标题、五点、A+、搜索词、Review/评分，判断是流量问题还是承接问题，避免误否相关词。
- **Review/Offer 归因**：`review audit` 识别质量、不可用、少件、尺寸、描述不符、售后等差评/Q&A 风险，并结合评分、评论数、价格判断是否应先控广告。
- **库存/利润联动**：`offer audit` 根据毛利率、目标 ACOS、库存天数、售价/竞品价、coupon、广告 ACOS 判断能不能放量。
- **竞品/类目分析**：`competitor audit` 识别竞品流量、ASIN 串号词、类目扩展候选、保护词命中和缺失核心词。
- **周期复盘**：`weekly review` 聚合动作队列、近期巡检、Scorecard、trace、影子台账，生成周报/复盘 Markdown。
- **自动预警**：`alert check` 检查动作队列、工具失败、影子台账、画像、知识库和磁盘空间；`--notify` 可发送到 stdout、通用 webhook 或飞书机器人。
- **本地计划任务**：`schedule set/list/run-due/run` 不常驻，可由 cron/systemd/awenOps 定时调用；alert 任务支持保存通知参数，`knowledge_sync` 可按小时检查官方来源并生成审核队列。
- **安全策略**：`policy init/show/check-path/check-command/explain-command` 管理 `~/.awen/policy.json`，可限制读写目录、命令 allow/deny，并对命令给出 allowed/risk/reasons。
- **Workspace 项目理解**：`workspace index/search/map/graph/inspect/explain` 离线扫描任意代码项目，跳过 `.git/node_modules/dist/build/venv` 等噪声，索引保存到 `~/.awen/workspaces/`，输出语言分布、重要文件、目录结构、符号摘要、搜索命中、依赖图、入口点、测试文件、配置文件和建议命令。`.github/workflows` 默认纳入索引，用于 CI/发版判断。
- **通用长任务**：`task create/list/show/start/step/status/log/resume/continue` 把复杂任务保存到 `~/.awen/tasks/`，记录步骤状态、阻塞原因、日志和结构化恢复提示；`/v1/tasks/{id}/resume` 可给 awenOps 读取下一步和续跑 prompt，`/v1/tasks/{id}/continue` 可直接续跑一轮。它是 Agent 执行长任务的进度台账，不是定时器。
- **Git/CI 只读工作流**：`gitops status/diff/workflows/release-plan` 查看仓库状态、diff 摘要、GitHub Actions workflow 和发版前检查；当前只读，真实 commit/push/release 后续接审批。
- **代码审查**：`codereview` 扫描 git diff 和未跟踪新文件，识别疑似密钥、危险 shell、宽异常捕获、生产代码无测试改动等确定性风险。
- **用户 Skill**：`skill create/audit/status/export-lock` 支持在 `~/.awen/skills/` 下创建个人 skill，审计触发词、正文和关联知识卡，查看用户覆盖/版本差异，并导出当前生效 skill lockfile。
- **生命周期管理**：`self status/backup/upgrade/uninstall` 识别安装方式、备份用户数据、输出升级/卸载计划；真实执行需要 `--execute` 并经过审批。
- **通用视觉**：`vision` 面向截图、UI、报表等通用视觉任务；`image vision` 继续作为 Listing 图片专用入口。默认只生成请求包，显式 `--call` 才会调用外部多模态模型。
- **图片视觉诊断**：`image audit` 先做本地资产预检查，并可导出多模态大模型审核 prompt；`image ocr` 识别图片文字（RapidOCR 优先，缺失时退 tesseract）；`image local` 跑本地 CV+OCR 量化并可用 `--prompt` 看到注入主脑的原文（就是下面 T3 那一档用的东西，纯本机、图片不出网）；`image vision` 默认生成 OpenAI/Claude/Gemini 请求包，显式 `--call` 时才真实调用外部多模态 API。

### 带图对话的三档降级链

给对话附图（`@图片路径`，或 awenOps 网页上传）时，awen **不要求主脑支持图片**。
它按下面三档自动降级，并在每轮明确告诉你走的是哪一档：

| 档 | 触发条件 | 实际行为 | 能做什么 |
|---|---|---|---|
| T1 主脑直读 | 当前主脑模型自带视觉（gpt-4o / claude / gemini / *-vl 等） | 图片直接进主脑上下文 | 全部 |
| T2 视觉旁路 | 主脑不支持图片，但配了视觉模型 | 由视觉模型代读成文字，回灌主脑 | 全部 |
| T3 本地量化 | 两者都没有 | 本地 CV + OCR 把图片量化成读数，回灌主脑 | 可测量的部分 |

T3 具体产出：尺寸/比例/分辨率、白底合规判定、主体占比与居中偏移、是否触边、
k-means 主色板、高频区（疑似文字）占比、感知哈希查重、OCR 文本与文字版面分布。
**全程本机运行，图片不出网。** 注入主脑的文本自带约束，明确要求模型区分"读数"与
"推断"，答不了的问题必须直说需要视觉模型——所以 T3 不会拿读数编造画面内容。

T3 做不到的是语义类判断：这是什么产品、版式意图、审美好坏、有没有穿帮。
需要这些就配一个视觉模型升到 T2。

配置 T2 的视觉模型（三选一）：

```bash
# 1) 完整视觉槽（推荐；自建网关/私有模型也用这个）
awen config set vision_slot '{"provider":"siliconflow","model":"Qwen/Qwen3-VL-30B-A3B-Instruct","base_url":"https://api.siliconflow.cn/v1","api_key":"sk-..."}'

# 2) 指定 provider 或模型，key 走环境变量
awen config set vision_model gemini

# 3) 什么都不配：只要任一 provider 配了 key 且目录里有视觉模型，会自动选中
```

awenOps 用户不需要在这里配——在「系统配置 → AI 服务 → 视觉模型」配一次，
会自动下推给 agent，网页和 CLI 共用同一个视觉模型。

模型名判不准时（自建网关常见），用 `awen config set vision_capable_override true|false|auto`
手动覆盖"主脑是否支持图片"的判定。
- **运行时间线**：`trace` 记录工具调用、耗时、失败，Scorecard 会汇总。
- **业务 Eval**：`awen eval` 固化广告决策 golden、知识召回、skill 召回和安全脱敏，避免迭代后质量退化。

## 七点五、店铺巡检与飞书闭环

`awen alert` 检的是 agent 自己（队列积压、trace 失败）；检**店铺**的是 `awen store health`。

### 三层巡检：频率由数据新鲜度决定

| 层 | 数据 | 延迟 | 建议节奏 | 命令 |
|---|---|---|---|---|
| L1 快照 | 库存、活动/关键词配置（接口无日期参数 = 当前状态） | 秒级 | 1 小时 | `awen store health --sid X` |
| L2 日内 | 当日累计报表多次采样做差分 | 小时级 | 1 小时 | `awen store health --sid X --layer l2` |
| L3 隔日 | 完整报表 + ASIN 利润 + 优化器候选 | T+1 | 每天 | `awen store health --sid X --layer l3` |

紧急异常靠**换更快的数据源**发现，不靠调低统计门槛 —— L1 的库存/配置类接口
没有时间参数，返回的就是此刻的状态。

每条结果都带**溯源**（`来源 领星 OpenAPI · 延迟约 5 分钟 · 120 行`），
取不到数时会明确报「数据缺口」——**「没告警」不等于「没问题」**。

### 建议按动作可逆性分档

| 类别 | 例子 | 能不能自动执行 |
|---|---|---|
| 止血型 | 降预算、降 bid、提预算 | 可逆、幅度封顶 15%，卡片上给「批准执行」 |
| 结构型 | 否词、加词 | 不可逆，需统计显著性，卡片会明示「这是不可逆操作」 |
| 建议型 | 补货、改价 | 只告警，agent 没有写通道 |

### 推到飞书

```bash
awen store health --sid 1863 --push --store-name "欧洲-UK"
```

卡片上的「批准执行」点下去 → 过幅度硬闸 → 过写开关 → 真写领星 →
卡片原地变绿显示审计号 + 回滚按钮。终端等价命令：

```bash
awen approval list                 # 待审批 / 已执行 / 已回滚
awen approval show <ID>            # 完整 intent 与证据
awen approval approve <ID>         # 等同于点「批准执行」
awen approval execute <ID>         # 写开关补开后重试
awen approval rollback <ID>        # 回滚已执行的
```

> **写开关默认关**。关着的时候点批准不会失败，而是记为「待执行」——
> 你的批准意愿仍然有效，`awen lingxing operate on` 之后
> `awen approval execute <ID>` 直接重试，不用重发卡片。

### 多个店铺

```bash
awen store list                              # 所有店铺，标注哪些未开通广告
awen store health --all-stores               # 一次跑完全部在营店铺
awen store health --sids 1863,1872           # 只跑指定的几个
awen store health --all-stores --exclude-sids 1870,1871
```

三件自动发生的事，不用配：

- **未开通广告的店自动跳过广告规则**。领星店铺列表自带这个标志位，
  `awen store list` 里标了出来。这类店过去会稳定报「参数不合法」，
  被当成取数故障反复告警且永不恢复。
- **逐店隔离**。某个店取数失败不影响其余店，坏的那个会如实报出来。
- **同款变体合并**。一个母体 ASIN 挂 30 个变体、评分都低时，
  报一条并注明「另有 N 个变体同样如此」，不是刷 24 条。
  门槛可调：`/threshold variants.collapse.min 5`。

### 定时跑起来

```bash
awen schedule set l1    store_l1    --every-minutes 20 --all-stores
awen schedule set l2    store_l2    --every-hours 1    --all-stores
awen schedule set daily store_daily --every-hours 24   --all-stores
awen schedule set appr-expire approvals_expire --every-hours 1
awen schedule list
```

`--all-stores` 让**一条**任务覆盖所有店铺；店铺增减不用改配置。
要盯固定几个店就用 `--sids 1863,1872`，单店仍可用 `--sid 1863`。

触发器见 `deploy/systemd/awen-schedule.timer`（每 5 分钟唤醒问一次"谁到点了"，
频率写在 `schedule.json` 里，改节奏不用 `daemon-reload`）。

**节奏**：L1 每小时 · L2 每 12 小时 · 早报每天 · 周报每周 · 月报每月，都能在
awenOps 系统配置 → 飞书里逐档开关和调间隔。周报/月报是**回顾**：本期指标环比 +
本期批了/执行了/回滚了几条 + 还没解决的问题，**不带审批按钮**（要动手的按钮在早报里，
两处都给会让同一个目标挂两条待办）。

**即时告警**：L1/L2 一发现异常就推带批准按钮的卡片，不用等早报。

**卡片怎么读**：标题给构成（紧急几条 / 注意几条 · 哪个店）；一条异常一个块，第一行是「出了什么事 · 谁」，下面是当前值与门槛/基线的对照；页脚小灰字是数据来源、跳过的规则和规则代码——排查时用得上，平时不用看。

**防刷屏**：同一条问题只在「正常 → 异常」那一刻报，持续中的静默（crit 每 4 小时、其余每 24 小时最多再提醒一次），消失时发一条「✅ 已恢复」；严重度升级视作新事件立即报；**取数失败那一轮不判恢复**。无异常且无数据缺口时不推送；早报例外（你要的就是每天确认一眼）；
数据源**连续**失败才告警（L1/L2 三次、早报两次），恢复后自动清零。
多店时早报合成**一张卡**：一店一行看状态，异常与"待你决定"跨店合并按严重度排序。

### 飞书里能做的

| 操作 | 怎么做 |
|---|---|
| 对话 | 直接发消息（默认只读，不会改广告） |
| 清上下文 | `/reset` |
| 看/改阈值 | `/threshold` · `/threshold ads.acos_breach.factor 1.8` · `/threshold reset` |
| 开写开关 | `/operate 120`，或点卡片上的按钮 |
| 批量批准 | 卡片上「全部批准」——**两步**，第一次只出确认卡 |

配置有两条路，**推荐第一条**：

1. **awenOps 系统配置 → 飞书 / Lark**。一处填完，凭据自动同步到这里；
   带一条按真实状态点亮的向导（凭据 → 权限 → 收消息的群 → 谁能点审批 →
   relay → 巡检开关 → 发一条真消息验收），审批人可以从群成员里勾选，
   不用去后台抄 `ou_` 开头的 ID。
2. 手工：凭据入 `~/.awen/.env`（`AWEN_FEISHU_APP_ID` / `_SECRET`），
   默认会话入 settings 的 `feishu_default_chat_id`，审批白名单入
   `feishu_allowed_senders`（**留空 = 谁都不能点**，这是安全默认，不是"未配置"）。

**接收端（卡片按钮 + 飞书对话）跟着 `awen serve` 自动跑**，装 awenAgent 时带上
飞书 extra 即可，不用再单独装服务、也不用点任何按钮：

```bash
pip install "awen-agent[feishu]"
```

（用 awenOps 的人不用管这条 —— 它的安装/更新已经带上了这个 extra。）
巡检节拍器同理，跟着 serve 走，不再需要 systemd timer。

想要进程隔离（把长连接和节拍器跑成独立服务）的话，两条命令：

```bash
pip install "awen-agent[feishu]"   # 飞书官方 SDK，42MB，只有用飞书才需要
awen relay install                 # 写 systemd 单元并启动；`awen relay status` 看状态
```

没有 systemd 的机器（含 Windows）用自己的进程管理器常驻
`python -m awen_agent.feishu_relay` 即可。它走长连接，**不需要开放任何公网端口**；
以 `~/.awen` 的配置为准、环境变量只作兜底，白名单改完立刻生效，不用重启。

**只发告警可以不装**；但不装的话，卡片上的「批准执行」按钮点了不会有任何反应
（配置向导第 5 步会红着告诉你这件事）。

## 八、模型与健壮性

- **多模型**：`awen model providers` 查看完整 provider 矩阵和能力标签；可用主脑包括 DeepSeek、Claude API、Gemini API、Gemini Code Assist OAuth 登录/token/probe 诊断、AWS Bedrock Converse、OpenAI 兼容、GitHub Copilot、通义、Qwen OAuth device-code/Qwen CLI 登录导入自动刷新、Kimi、Z.AI/GLM、豆包、MiniMax、OpenRouter、Nous(API key)、xAI、Ollama/本地和自定义网关。
- **降级链**：`awen config set fallback_models deepseek-reasoner,claude-sonnet` —— 主脑限流/挂了自动切有 key 的备用模型继续。
- **重试/退避**：429/5xx/网络错误自动重试 + 指数退避；4xx 直接报错。
- **可中断**：对话里 Ctrl+C 停本轮、不杀会话。

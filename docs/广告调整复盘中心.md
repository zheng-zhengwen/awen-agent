# 广告调整复盘中心

这套能力回答四件事：**改了什么、为什么改、当时影响哪些投放对象、后来观察到什么变化**。
它不是财务对账，也不是自动回滚系统；技术写入审计、审批安全链和既有优化阈值保持原样。

## 1. 组件与边界

| 组件 | 责任 | 不负责 |
|---|---|---|
| `adjustments.py` | 不可变动作账本、幂等、注释、复盘 revision、同步状态 | 拉广告报表、执行广告写入 |
| `operation_sources/lingxing.py` | 调领星 v2 操作日志并规范化事件 | 用效果数据猜动作、跨来源模糊合并 |
| `adjustment_scope.py` | 用投放商品和 variation/Listing 快照记录父子 ASIN 范围及捕获时点 | 把父 ASIN 变成写入目标 |
| `adjustment_review.py` | 时间窗、汇总公式、样本与方向信号、非重叠权重 | 因果证明、生成执行动作 |
| `adjustment_report.py` | 按对象/广告组/活动/父体/店铺装配数据并追加复盘 | 绕过 `metrics` 直连供应商字段 |
| `service.py` / CLI / Agent / MCP | 对 awenOps、人和 Agent 提供脱敏投影 | 回显 raw provider payload 或凭据 |

事件和指标是两条独立链：

```text
awenOps/上游推送 ─┐
awen 成功写入 ────┼─> canonical adjustment event ─> adjustments.db
领星操作日志 ─────┘                                 │
                                                    ├─> 3/7/14/30 天复盘 revision
official/LingXing/MCP metric sources ─> metrics ────┘
```

复盘如果发现负向信号，只会形成只读结论。任何下一步调整都必须由正常优化器重新计算，再经过现有
护栏、审批和写开关；复盘本身不会偷偷创建 intent。

## 2. 一条动作的完整流程

1. **决策时**：记录目标、当前值、建议值、规则、目标 ACoS/盈亏线、3/7/14/30 天证据、样本量和
   人工理由。外部人工操作拿不到理由时明确写 `reason_status=missing`，以后可追加注释，不能把
   模型推断冒充原始理由。
2. **执行后**：只有真实成功的 awen 写入进入账本；dry-run、硬闸拦截和失败请求不入业务动作账本。
   同时保留原有审批状态与 `audit.jsonl` 技术审计。原生写入的绝对时刻精确记录为 UTC instant，T0
   日期只从 intent、本地店铺缓存或本地 Amazon 配置解析站点 IANA 时区；不会在写成功后为了元数据
   再发网络请求。解析不到时按 UTC 降级，并写入 `local_date_confidence=low` 警告。
3. **范围记录**：按动作粒度找到投放子 ASIN，并从 variation 或 Listing 快照展开到父 ASIN 和未投放
   兄弟体。上游随动作提交的是 T0 快照；awen 原生候选会在进入审批/执行链前按店铺批量捕获
   `decision_snapshot`；补拉历史领星日志时只能拿到同步时快照。后两者都会保存真实 `snapshot_at` 并
   标为 `action_time_exact=false`，不能把决策时或同步时的当前关系冒充历史执行时关系。
4. **数据成熟**：T0 当天排除，T+1 起进入观察；动作后满 3、7、14、30 天并留出至少一天归因
   回补后进入到期队列。
5. **多层复盘**：对象 → 广告组 → 活动 → 父体（投放子体、未投放兄弟体、父体总计）→ 店铺总计，
   并另列 advertised→purchased ASIN、父体利润、自然/广告排名与当前库存上下文。缺哪层就显示数据
   缺口，其余层继续计算。
6. **形成 revision**：保存窗口、原始汇总、变化值、日期覆盖、置信度、混杂因素、来源和边界声明。
   数据缺口/样本不足会在 24 小时冷却后有限重试（每窗口最多 5 个自动 revision）；数据源回补或人工
   重跑会追加 revision，旧版本仍可追溯。
7. **周期呈现**：日报、周报、月报展示本期动作数、缺理由数和最新复盘结论，不重复生成审批。

## 3. 父 ASIN、子 ASIN 与投放子集

对精确 T0 快照，令 `C(P)` 为父 ASIN `P` 在动作时点的全部有效子体，`A(P,T0)` 为动作实际覆盖
的投放子体：

- 投放子体：`A(P,T0)`；
- 未投放兄弟体：`U(P,T0) = C(P) - A(P,T0)`；
- 父体总计：对 `C(P)` 的销量、销售额、订单等分子分母重新汇总；
- 父 ASIN 是分析分组，不会传给领星/Amazon Ads 写接口。

活动可能同时覆盖多个父体，因此 scope 行为每个子体保留 `parent_asin`，不是只在动作上放一个父体
字段。`advertised_asin` 表示广告展示的商品，`purchased_asin` 表示归因订单实际购买的商品；跨子体
购买时两者不同，不能合并成一个 `asin`。购买商品报告先按 `advertised_asin` 绑定触发广告的投放
子体，再把 `purchased_asin` 分为投放子体购买和未投放兄弟体 halo；多父体范围缺少
`advertised_asin` 时直接显示 `data_gap`，不会仅凭买到哪个子体反推是哪个父体广告带来的。单父体
缺该字段时允许降级归组，但固定标为低置信度。

范围来源按可信度依次为：上游在 T0 推送的明确快照；awen 原生候选进入审批/执行链前捕获的决策时
快照；同步时的投放商品 + variation/Listing 快照；只有投放商品但没有父子关系的部分快照。映射失败
不阻止动作事实入库，只会降低
`mapping_confidence`。同一个幂等事件日后重放时，如果原来缺父体范围而现在映射恢复，可以补充 scope
和证据；动作本身、前后值和原始理由不会改写。

## 4. 数据模型

数据库为 `~/.awen/adjustments.db`，启用 SQLite WAL、事务和忙等待：

| 表 | 内容 |
|---|---|
| `adjustment_batches` | 一次同店、同来源导入批次及脱敏元数据 |
| `adjustment_actions` | 不可变动作事实、前后值、对象、操作者、站点本地时点、原始理由；自由文本会脱敏 |
| `adjustment_scope_asins` | parent / advertised_child / unadvertised_sibling 及真实 `snapshot_at` |
| `adjustment_evidence` | 决策与映射证据；写前递归清除 token/password/secret/API key/Authorization/cookie |
| `adjustment_reviews` | 每个动作×3/7/14/30 天的 append-only revision |
| `adjustment_sync_state` | 每店来源模式、push 新鲜度、领星游标和分维度错误 |

有稳定上游 ID 时用 `(sid, source, source_event_id)` 幂等；领星没有稳定日志行 ID，因此使用由对象、
时点、操作者和前后值组成的 SHA-256 指纹，并仍按 `sid + source` 隔离。领星响应的 `request_id` 只代表
一次查询链，保存在同步诊断中，**绝不当作事件 ID**。

## 5. 领星操作日志契约

适配器调用 `POST /pb/openapi/newad/apiLogStandard`，仅该请求附加 `X-API-VERSION: 2`。必填字段为
`sid`、`log_source`、`sponsored_type`、`operate_type`、`start_date`、`end_date`；单次不超过一个月，
v2 的 `offset` 是从 0 开始的行偏移，总数读取响应顶层 `total`。分页串行执行，遵守现有 OpenAPI 限流。
领星文档中的 `function_name=WebPage` 是功能来源，不是动作语义；竞价和预算方向从
`BID_*` / `BUDGET_*` 前后值判断，未知 code 原样保留。

一期默认同步 SP 的 campaigns、adGroups、productAds、keywords、negativeKeywords、targets 和
negativeTargets。每个维度独立失败：一个维度取不到不会抹掉已成功导入的维度，失败会进入 sync state。
站点裸时间先按店铺 marketplace 映射到 IANA 时区；带 offset 的上游时刻也会投影回站点 IANA 时区，
保证 T0 取站点本地日期。映射未知时退回 UTC，并在事件证据、同步状态和同步响应中返回低置信度警告。

来源模式：

- `push`：只收上游推送，不主动拉领星；
- `lingxing`：始终以领星日志同步；
- `hybrid`（默认）：36 小时内收到 push 就跳过领星，push 变旧后再拉领星兜底；
- `--force` 只用于人工补数，会绕过新鲜度判断。不同来源没有共同主键，所以不做模糊去重。

## 6. 复盘口径

动作日为 T0。h 天复盘使用：

- 前窗：`T-h ... T-1`；
- 后窗：`T+1 ... T+h`；
- 两窗严格等长，T0 排除；
- 展示累计 3/7/14/30 天，但正式趋势拆成 D1–D3、D4–D7、D8–D14、D15–D30，避免重叠窗口
  重复计权。

非重叠权重遵循操作工程规范：普通竞价/方向未知的预算变化 35/30/20/15%，暂停或新增否词
10/20/30/40%，明确扩量（加竞价、加预算、启用或删除否定对象）20/35/30/15%。删除否定对象与
新增否词语义相反，不会被字符串中的 `negative` 误判为控量。每段先换算日均分子分母，再加权重算
比率，不能平均各 ASIN 的 ACoS/CVR。

基础公式：

- `CTR = clicks / impressions`
- `CVR = orders / clicks`
- `CPC = spend / clicks`
- `ACoS = spend / sales`
- `ROAS = sales / spend`

分母为 0 时返回 `null`，不返回无穷大，也不拿 0 冒充可比较结果。

全链接业务层另汇总 `sessions`、`units`、`orders`、`sales`，并重算 `unit_session_rate` 和
`order_session_rate`。日期覆盖 100% 为 high、至少 80% 为 medium、至少 50% 为 low；任一前后窗
低于 50% 直接记为 `data_gap`，不会因为单日订单很多就输出“改善”。调用方提供了非空数据、但没有
任何一行命中当前活动、广告组或父子 ASIN 范围时同样记为 `data_gap`，不会把范围外数据当成零表现。
利润和排名是等长前后窗上下文；库存只有复盘时快照，会固定标注 `snapshot_only`，不能解释成库存的
前后变化。

结论枚举：`waiting_for_data`、`data_gap`、`insufficient_sample`、`positive_signal`、
`stable_positive`、`neutral`、`negative_signal`、`confounded`。置信度分别评估 sample、data、mapping、
comparability，总置信度取最弱项。所有结果固定带：

> 这是时间窗相关性观察，不能归因为单次广告调整的因果结果。

## 7. canonical 指标与一期可用性

一期注册以下扩展契约：variation snapshot、ad-group config/report、target config/report、placement report、
advertised-product report、purchased-product report、ASIN business daily、parent-ASIN profit、
ASIN×keyword ranking daily。

当前仓库已经核实并接通领星的 `sp_ad_groups`、`sp_targets`、`sp_target_report` 路由。其余契约等待
上游推送、Amazon 官方源或 LingXing MCP 实现；在源未接通前返回明确 data gap，不虚构路由或数据。

## 8. 使用方式

```bash
# 查看与筛选
awen adjustment list --sid 1863
awen adjustment list --sid 1863 --parent-asin PARENT --date-from 2026-08-01 --date-to 2026-08-31
awen adjustment show <调整ID>
awen adjustment summary --sid 1863 --days 30

# 默认 hybrid；补拉领星操作日志
awen adjustment sync --sid 1863 --start-date 2026-08-01 --end-date 2026-08-31
awen adjustment sync --sid 1863 --source-mode lingxing --start-date 2026-08-01 --end-date 2026-08-31

# 人工补理由；原始 reason 不会被覆盖
awen adjustment annotate <调整ID> --text "库存进入清仓阶段，降低非核心词竞价" --operator wen

# 手工重跑一个窗口，会追加 revision
awen adjustment review <调整ID> --horizon 7
```

计划任务可注册 `adjustment_sync` 和 `adjustment_review`。服务端提供：

- `GET /v1/adjustments`、`/summary`、`/{id}`、`/{id}/reviews`
- `POST /v1/adjustments/import`、`/sync`、`/{id}/annotation`、`/{id}/evaluate`

上游导入以 canonical event 数组为主体；同一请求必须属于同一 `sid` 和 `source`。API 使用现有 Bearer
认证，公开详情不返回 `raw`；访问令牌仍由原有领星认证模块刷新和保存，复盘数据库不复制凭据。
列表响应返回 `next_cursor`，下一页应优先传 `?cursor=...`，避免同一秒内多条动作被跳过；旧的
`next_before` 只为兼容保留。

`/{id}/evaluate` 可由已完善数据接入层提交对象级 `rows`，以及 `campaign_rows`、`ad_group_rows`、
`business_rows`、`store_rows`、`purchased_rows`、`profit_rows`、`ranking_rows`、`inventory_rows` 和
`confounders`。这些输入只保存汇总投影与来源标记，不保存供应商原始报表；投放商品与购买商品始终
分栏，兄弟体购买作为 halo 观察展示。显式传入空数组表示“调用方已提供但没有可用行”，会保留
caller provenance 并显示 `data_gap`，不会把空库存或空上层广告报表解释成零表现。同步全部成功返回
HTTP 200，部分维度成功返回 207，所有维度均失败返回 502。计划任务支持单店、多店和 `all`，未
配置广告的店会明确跳过，一个店失败不阻断其他店。

对话 Agent 暴露四个只读工具，反向 stdio MCP 只暴露 list/detail。它们属于 work 路线，不进入
只带公共知识检索工具的 quick 路线。
